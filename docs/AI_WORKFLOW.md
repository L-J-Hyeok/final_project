# AI 작업 효율화 워크플로우 (AI Workflow)

이 문서는 Codex와 Google Antigravity가 `final_project`에서 공통으로 준수하는 작업 효율화 지침이다.
유일한 개발 규칙 원본인 [DEVELOPMENT_RULES.md](DEVELOPMENT_RULES.md)를 보완하며, 불필요한 파일 재분석·토큰 낭비·맥락 손실을 방지하고 에이전트 간 안전하고 빠른 인수인계를 목적으로 한다.

---

## 1. 세션 내 맥락 재사용과 중복 분석 방지

1. **세션 내 파일 재분석 금지:**
   - 동일 대화 세션에서 이미 읽거나 파악한 소스 코드, 스키마, 기획 문서는 반복해서 다시 읽지 않고 기존 맥락을 재사용한다.
   - 사용자가 명시적으로 재확인을 요청하거나 외부에서 파일이 변경된 경우에 한하여 필요한 부분만 선별적으로 다시 읽는다.
2. **타겟 검색 우선 (Selective Search):**
   - 대형 소스 코드, 기획 문서, 대형 JSON(`products.json`, 정규화 JSON 등) 전체를 무조건 한 번에 열지 않는다.
   - 필요한 함수, 클래스, 테이블 모델, 특정 키 필드 위주로 `grep`, 심볼 검색, 부분 줄 읽기(range read)를 우선 사용한다.
3. **불필요한 전체 저장소 스캔 차단:**
   - 프로젝트 전체 트리나 무관한 디렉터리를 습관적으로 탐색하지 않으며, 현재 작업 디렉터리(`front/`, `backend/`, `docs/`)에 집중한다.

---

## 2. 세션 전환 및 에이전트 인수인계 (Handoff)

1. **인수인계 기준 문서:**
   - 새 세션이 시작되거나 Codex ↔ Antigravity 간 도구가 전환될 때는 [AI_HANDOFF.md](AI_HANDOFF.md)를 최우선 기준으로 시스템 상태를 파악한다.
   - `AI_HANDOFF.md`의 현재 스냅샷을 확인한 후 작업에 직접 관련된 파일만 확인하며, 전체 프로젝트 파일 전수 조사를 금지한다.
2. **누적 로그 점진적 확인 (Checkpoint 기반):**
   - [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md)는 전체를 처음부터 읽지 않는다.
   - `AI_HANDOFF.md`에 기록된 마지막 반영 로그 ID(또는 타임스탬프) 이후의 신규 항목만 확인한다.
   - 마지막 체크포인트 이후 새 로그가 없다면 누적 로그 읽기를 완전히 생략한다.
3. **변경 사항 범위 확인 (Diff 우선):**
   - 기존 파일의 수정 여부는 전체 파일을 읽는 대신 `git status` 및 `git diff`를 통해 실제 변경된 diff 범위와 신규 미커밋 파일만 정확히 확인한다.
4. **현황 문서의 선택적 확인:**
   - [CURRENT_STATUS.md](CURRENT_STATUS.md)는 누적 로그와 구분하여 최상단 최신 상태 요약 및 최근 추가된 섹션만 읽는다.

---

## 3. 작업 범위 및 수정 원칙

1. **단일 기능 집중 (Single Task Focus):**
   - 사용자 요청 1회당 주요 기능 하나만 수정한다. 무관한 리팩토링, 디렉터리 구조 변경, 포맷팅 수정을 병행하지 않는다.
2. **미커밋 변경사항 사전 확인:**
   - 작업 착수 전 `git status`로 이전 세션의 미커밋 변경이나 임시 파일 상태를 파악하여 작업 충돌을 예방한다.
3. **점진적·비파괴적 수정:**
   - 기존에 검증된 백엔드/프론트엔드 기능을 임의로 재작성하거나 삭제하지 않는다.

---

## 4. 테스트 실행 및 재시도 제한

1. **관련 테스트 우선 실행:**
   - 전체 테스트 스위트를 매번 실행하지 않고, 수정한 모듈에 직접 관련된 단위/통합 테스트만 선별하여 실행한다.
2. **동일 오류 재시도 상한 (최대 2회):**
   - 동일한 테스트 실패 또는 런타임 오류에 대한 무의미한 반복 재시도는 최대 2회로 제한한다.
   - 2회 연속 동일 원인으로 실패하면 즉시 중단하고, 근본 원인과 대안을 사용자에게 보고한다.
3. **전체 테스트 및 외부/유료 API 호출 제한:**
   - 전체 테스트 스위트 일괄 실행 및 실제 과금이 발생하는 Gemini Live API 호출은 작업 마무리 검증 단계나 사용자의 명시적 요청이 있을 때만 최소한으로 실행한다.
   - 단위 테스트 검증에는 Mock AI 어댑터를 기본 활용한다.

---

## 5. 인수인계 문서(AI_HANDOFF.md) 갱신 규칙

1. **상태 변경 시에만 갱신:**
   - DB 적재, 핵심 API 구현, 마이그레이션 적용, 주요 테스트 통과 등 아키텍처/기능의 중대한 상태 변화가 있을 때만 갱신한다.
2. **단일 스냅샷 유지:**
   - `AI_HANDOFF.md`에는 과거 작업 이력을 누적하지 않는다. 항상 '현재 시점의 확정된 최신 스냅샷'만 단일 버전으로 유지한다.
3. **필수 기재 항목:**
   - 현재 기술 스택, DB 상태(모델/변형/관측치 수), 검증 현황, 특별 주의사항/제약조건, 바로 다음에 진행할 우선 작업을 명시한다.
4. **체크포인트 ID 기록:**
   - 갱신 시점의 [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) 마지막 항목 타임스탬프 또는 헤더를 기록하여 다음 세션의 탐색 기준점을 명확히 제공한다.

---

## 6. 새 세션 작업 착수 체크리스트

새 세션이나 도구 전환 시 AI 에이전트는 다음 순서로 작업을 시작한다:

1. `docs/AI_HANDOFF.md`를 읽고 현재 시스템 상태, 제약조건, 다음 작업을 확인한다.
2. `git status`로 미커밋 변경 파일 및 신규 추가 파일을 확인한다.
3. `AI_HANDOFF.md`의 체크포인트 이후 `docs/DEVELOPMENT_LOG.md`에 추가된 내용이 있는지 확인한다 (없으면 생략).
4. 이번 요청에서 다룰 단일 대상 파일에 대해서만 타겟 검색 및 수정을 진행한다.
5. 수정 완료 후 관련 테스트를 실행하고, 주요 상태 변화가 있을 경우에만 `AI_HANDOFF.md`를 갱신한다.

---

## 7. 보안 및 무결성 기본 규칙 준수

- [DEVELOPMENT_RULES.md](DEVELOPMENT_RULES.md)의 모든 보안 규정은 최우선으로 유지된다.
- `backend/.env` 및 실제 비밀정보 파일은 절대 직접 열람·수정·출력하지 않는다.
- Git commit 및 push는 사용자의 명시적 승인/요청 없이 수행하지 않는다.
- 데이터베이스의 실제 카탈로그 데이터(49모델·31변형) 및 사용자 데이터를 임의로 초기화하거나 삭제하지 않는다.
