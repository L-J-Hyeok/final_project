# 기기로움 백엔드 로드맵

기준일: 2026-11-13 (Asia/Seoul). [팀 요구사항](TEAM_REQUIREMENTS.md)은 확정 목표, [통합 설계](INTEGRATED_RECOMMENDATION_DESIGN.md)는 책임 경계·제안·미결정 사항을 정의한다. 이 문서는 후속 구현 순서 제안이며 이번에 아래 작업을 실행한 것은 아니다.

## 출발점과 협업 경계

기존 Express·Sequelize·MySQL, 인증·CSRF·프로필·소유권·후보 검증·추천 이력·Gemini 어댑터를 재사용한다. 기존 ID/FK·사용자 데이터·검증값을 보존한다. 스마트폰 우선이며 현재 6개 제품군의 DB·평가 엔진이 완성됐다고 가정하지 않는다.

Antigravity의 다나와 Phase 5는 별도 진행 중이다. 이번 문서 작업에서 관련 코드·DB·프론트 수정, 실행 검증 또는 완료 판정을 하지 않았다. 공용 상태 문서도 변경하지 않았다. Phase 5 종료 후 담당자의 변경 파일·API 계약·가격 검증 결과를 인계받는 것이 다음 작업의 선행 조건이다.

## 단계와 완료 기준 — 모두 향후 작업

| 순서 | 범위 | 완료 판단 기준 |
|---|---|---|
| 1 | Phase 5 인계 및 스마트폰 통합 안정화 | 실제 가격/참고가/출고가·옵션·유효기간 계약 확인, 격리 환경의 인증→프로필→보유 기기→추천→이력·비교 흐름 검증. 이전 감사 지적은 최신 코드로 재확인 |
| 2 | DB·API·평가 계약 합의 | DB 담당과 모델/옵션·측정 근거·설정 버전 합의, 공개/개발 DTO 분리, 기존 API 호환성 및 이력 보존 명시 |
| 3 | 범용 로컬 평가 코어를 스마트폰으로 검증 | 필수 필터·호환성·결측·정규화·개인 가중치·가성비·결정적 순위 구현. Mock 점수와 실서비스 코어 구분. 내부 수치 사용자 응답 비노출 |
| 4 | 전문 성능 자료 연동 | 이용 권한 확인된 소수 지표부터 수집/AI 정리·검증·승인·캐시. 버전·환경 불일치 거부와 출처 추적 검증 |
| 5 | AI 역할 전환 및 업그레이드 차별화 | AI 순위 생성에서 로컬 최종 순위+AI 설명으로 전환. KEEP/REPLACE/DEFER/CLARIFY, 불편별 개선·비교 불가, 비용·소유권·근거 재검증 |
| 6 | 제품 비교 고도화 | 기존 UI 유지, 로컬 우세/동률/차이/자료 부족·불가 구분, 개인 선호 설명, 선택적 AI 설명, 추천 옵션 ID와 비교 연결 |
| 7 | 구매 보조 판단 | 선택적 추가 투자, 확인된 공식 일정, 관측 가격 변화, 유지 판단. 예산 자동 완화·루머 단정·미래 가격 보장 차단 |
| 8 | 이벤트·뉴스 API | 이벤트 조건/유효기간/공식 출처, 뉴스 출처/발행일/제품군/원문/요약 계약과 권한 검증. UI는 프론트 담당 |
| 9 | 6개 제품군 확대 | 제품군별 승인 데이터·평가 메타데이터를 준비한 순서로 적용. 워치/이어폰의 기능·호환성 중심 평가. 미준비 제품군 비활성 |
| 10 | 원본 정상 동작 검증 및 팀 통합본 | 스마트폰 핵심 흐름과 공개·보안·가격·실패 처리 검증 기록. 원본 보존 후 비밀값/사용자 데이터 제외 복제, Mac·Windows·개인 DB·마이그레이션·시드·공용 계약·GitHub 협업 준비 |

3~4단계는 합의된 근거 계약을 토대로 점진적으로 병행할 수 있으나 미검증 성능을 채운 뒤 나중에 검증하는 방식은 금지한다. 다른 제품군의 공개는 각 데이터·평가 검증 후 진행한다. PC-FIT 부품 DB·호환성·전체 견적 최적화는 별도 후속 TODO이며 이번 범용 단품 추천 완료 조건에 포함하지 않는다.

## 후속 검증 계획 — 이번 미실행

[기존 테스트 계획](TEST_PLAN.md)을 대체하지 않고 다음 항목을 해당 구현 단계에서 추가한다.

- 동일 입력·동일 근거/가격/설정 버전의 순위 재현, 개인 선호 변화에 따른 합리적 순위 변화.
- 예산·필수 조건·호환성 위반 차단, 공개 승인 모델/옵션만 후보화, 실제 옵션 ID 보존.
- AI의 제품 추가·순위 변경·수치 조작·외부 문자열 지시 거부, 내부 점수·가중치 DTO 비노출.
- 자료 누락·측정 버전/환경 불일치·권한 미확보·캐시 만료 처리, 근거 갱신 후 이력 재현성.
- 가격 NULL·개발용 가격·배송비·조건부 할인·만료 처리, 초과 예산 안내의 기본 순위 분리.
- 일반 추천(기기 없음)과 업그레이드(소유 기기 필요) 구분, 네 가지 판단 및 불편 해결 근거 확인.
- 기기 수정/삭제 후 과거 이력 보존, 명시적 개인정보 삭제, 현재 유효성 표시.
- 비교 숫자/정성 근거 일치, AI 실패 시 수치 비교 유지, 6개 제품군 설정 격리.
- Mock 중심 검증 후 별도 승인한 실연동 검증. 실제 사용자 데이터·공용 DB에 테스트 쓰기를 하지 않음.

## 다음 합의가 필요한 사항

1. DB 담당: 제품군별 상세 구조와 옵션 식별, 근거·평가 버전 저장 계약.
2. 팀: 평가 항목·가중치·정규화·동률·자료 충족도·업그레이드 유의미성 기준.
3. 데이터 담당: 전문 자료 수집·저장·표시·AI 이용 권한, 승인 책임과 갱신 정책.
4. 백엔드: AI 설명 실패 응답·재시도/비용 한도, 내부 수치 접근 통제.
5. 프론트 담당: 기존 디자인을 유지한 결과 계약 연결, 향후 통합본의 뉴스/이벤트 UI 범위.

이번 생성 문서 3개는 공식 회의 요구사항과 후속 설계 기준이며, 구현·테스트·배포·Phase 5 완료 기록이 아니다.
