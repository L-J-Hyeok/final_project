# 기기로움 백엔드 로드맵

기준일: 2026-11-13 (Asia/Seoul). [팀 요구사항](TEAM_REQUIREMENTS.md)은 확정 목표, [통합 설계](INTEGRATED_RECOMMENDATION_DESIGN.md)는 책임 경계·제안·미결정 사항을 정의한다. 이 문서는 후속 구현 순서 제안이며 이번에 아래 작업을 실행한 것은 아니다.

## 출발점과 협업 경계

기존 Express·Sequelize·MySQL, 인증·CSRF·프로필·소유권·후보 검증·추천 이력·Gemini 어댑터를 재사용한다. 기존 ID/FK·사용자 데이터·검증값을 보존한다. 스마트폰 우선이며 현재 6개 제품군의 DB·평가 엔진이 완성됐다고 가정하지 않는다.

Antigravity의 다나와 Phase 5는 별도 진행 중이다. 이번 문서 작업에서 관련 코드·DB·프론트 수정, 실행 검증 또는 완료 판정을 하지 않았다. 공용 상태 문서도 변경하지 않았다. Phase 5 종료 후 담당자의 변경 파일·API 계약·가격 검증 결과를 인계받는 것이 다음 작업의 선행 조건이다.

## 단계와 완료 기준 — 모두 향후 작업

위 순서는 확정한 개발 우선순위이며 이번 문서화로 구현 완료된 단계는 없다. 3단계는 확보된 검증 자료만 사용하고 미확보 성능을 생성하지 않는다. 실제 가격 계약 확정 전 임의 연동하지 않는다.

[기존 테스트 계획](TEST_PLAN.md)을 대체하지 않고 다음 항목을 해당 구현 단계에서 추가한다.

- AI의 제품 추가·순위 변경·수치 조작·외부 문자열 지시 거부, 내부 점수·가중치 DTO 비노출.
- 자료 누락·측정 버전/환경 불일치·권한 미확보·캐시 만료 처리, 근거 갱신 후 이력 재현성.

## 모델 중심 추천과 후속 대화 단계

- 현재: 전체 적격 구매 구성을 서버에서 평가하고 모델당 한 구성씩 최대 3개를 선택한다. Gemini 설명에는 선정된 구성만 전달한다.
- 6단계 구현: 스마트폰 추천·업그레이드에 원문과 확인된 답변을 보존하는 세션 상담 및 질문 UI를 추가했다. 이후 실제 Gemini 분석 결과와 질문 정책의 품질을 검증하고, 다른 제품군은 별도 단계로 진행한다.

- 7-2단계에서 스마트폰 실측 저장·검증·동일 기준 비교 기반을 추가했다. 7-3단계는 출처의 저장·인용 권한과 시험 조건을 확인한 소수 자료를 검수하고, 실제 모델·SKU에 연결한 뒤 활용 범위를 평가한다.

- 7-3단계에서 개발 MySQL에 006을 적용했다. 공개 자료 조사에서 국내 모델·시험 환경·저장 및 서비스 표시 조건을 모두 충족하는 자료를 확보하지 못해 실측 등록은 보류했다. 이용 범위가 확인된 동일 시험 원본을 확보한 뒤 등록하고, 실제 자료가 포함된 추천·업그레이드 API를 검증한다.

- 7-4단계에서 검증된 CPU·GPU 실측의 로컬 점수 반영을 합성 자료로 검증했다. 실제 자료 확보 순서는 저장·표시·파생 평가가 허용된 출처 확보, 동일 시험의 국내 기기 표본 수집, 실제 후보 커버리지 검증이다. Gemini 검색 결과 이용은 공급자 허용 범위 확인 후 별도로 결정한다.

- 7-5단계에서 승인 URL 읽기와 CPU·GPU·게임·카메라·배터리 평가를 연결했다. 7-6단계에서 FixIndex와 EPREL 배터리 자동 탐색, 실제 iPhone 2개 모델의 Gemini 추출·점수 반영을 확인했다. 다음 단계에서는 자동 이용이 허용된 CPU·GPU·게임·카메라 공급 경로와 동일 시험의 모델 커버리지를 확보한다.

- 7-7단계는 공개 44모델의 배터리 소스 대조와 부분 실측 보정을 완료했다. CPU·GPU의 공식 인증 API 조건 확인, 비교 가능 게임·카메라 공개 자료 확보, 삼성 국내 모델의 동일 조건 배터리 시험 확보가 다음 단계다.

- 7-8단계는 공개 모델의 원본 칩셋 표기 24종을 22개 확인 가능한 조회 키로 정리했다. 공식 CPU/GPU 공급권이 확보되면 Geekbench 6 CPU, 동일 API의 GPU, UL 모바일 동일 프로토콜 측정 순서로 유효 커버리지를 검증한다.

- 7-9단계에서 배터리 실측의 Gemini 읽기부터 추천·업그레이드 HTTP 응답까지 격리 스키마에서 검증했다. [팀 실행 및 HTTP 계약](ARCHITECTURE.md#7-9-성능-조회와-팀-인계)을 기준으로 프론트·데이터 작업을 병행한다. CPU·GPU·게임·카메라에 쓸 수 있는 공급과 Search Grounding 전용 검색 표시 화면은 후속 작업이다.

## 8단계 공통 카탈로그와 제품군 확장

| 단계 | 현재 상태와 다음 결과 |
| --- | --- |
| 8-1 공통 제품·SKU·가격 | 007, Sequelize 모델·검증, 공개 조회 API 구현과 격리 MySQL 검증 완료. 개발 DB 적용은 대기. 스마트폰은 기존 DB에서 연결한다. |
| 8-2 공통 제품 비교 | 공통 모델·SKU 계약으로 비교 조회를 구현한다. 저장 용량·연결 방식 등 실제 옵션을 선택하고 제품군별 사양과 수집 당시 참고 가격을 표시한다. 다른 제품군 데이터는 팀원 검수 후 등록한다. |
| 8-3 공통 추천·업그레이드 | 기존 자연어 분석, 프로필, 필수 조건, 가격·근거 검증을 재사용한다. 제품군별 평가와 보유 기기 연결을 각각 추가한다. |
| 8-4 관리자 | 기존 관리자 권한으로 모델·SKU·사양·출처·가격을 수정하고 검증 및 공개 전환 이력을 남기는 API와 대시보드를 연결한다. |
| 8-5 통합 검증·인계 | 6개 제품군의 승인 샘플로 조회→비교→추천/업그레이드→관리자 흐름, 공용 계약, 실행·적용 절차를 확인한다. |

PC-FIT은 별도 후속 작업으로 유지한다.

8-2 진행 결과는 [공통 비교와 검증 입력 계약](ARCHITECTURE.md#8-2-제품-등록과-공통-비교)에 기록했다. 개발 DB 007과 신규 5제품군의 실제 사양·SKU 등록 및 6제품군 비교 API까지 확인했다. 신규 가격은 사용 가능 근거가 있는 관측을 확보하면 같은 입력 경로로 연결한다. 8-3은 공개 모델·SKU·사양으로 후보 조회를 시작하고, 가격이 없는 구성은 예산·가성비 평가에서 제외한다.

8-2.5에서는 조원 프로젝트(`pc_final-main/backend/src/data/products.json`)의 비스마트폰 데이터를 정규화·검증해 신규 59모델·67 SKU를 공통 카탈로그에 통합(신규 5개 제품군 총 64모델·77 SKU, 6개 제품군 공개 총 108모델·387 SKU)하고, 다나와 실가격 56건(태블릿 26, 노트북 9, 스마트워치 7, 무선이어폰 12, 스피커 2)을 `catalog_price_observations`에 연결했다. 8-3 범용 추천 엔진은 이 6개 제품군 공개 모델·SKU·사양·출처와 마지막 정상 참고 가격(스마트폰 93건, 신규 5개 제품군 56건)을 후보 조회 및 가성비 평가 입력으로 바로 사용한다.

8-3A에서는 기존 스마트폰 추천 엔진(`smartphone-ranker-v2`)을 보존한 채 태블릿·노트북·스마트워치·무선이어폰·스피커 5개 제품군의 로컬 평가 엔진(`catalog-recommendation-engine.js`), Gemini 자연어 분석 확장, 추천 API(`POST /api/recommendations` `category` 지정 및 `POST /api/catalog/:category/recommendations`)를 구현·검증했다. 보유 기기 기반 업그레이드 판단(`REPLACE`/`KEEP`/`DEFER`/`CLARIFY`) 확장은 다음 8-3B에서 진행한다.

8-3B에서는 신규 5개 제품군 보유 기기 등록(`catalog_sku_id`/`catalog_model_id` 및 수동 사양·구매가·불편사항 연결)과 범용 업그레이드 판단 엔진([`catalog-upgrade-advisor.js`](../backend/services/catalog-upgrade-advisor.js))을 구현하여 6개 제품군 전체의 추천·업그레이드 백엔드를 완성했다. 다음 단계는 **8-4 관리자 API 및 대시보드**다.
