## 2. Supabase (PostgreSQL) 전환 사전 분석

> 이번 단계에서는 설계 분석만 수행하며, 실제 PostgreSQL 코드 구현 및 연결은 진행하지 않는다.

### 2.1 DB 연결 및 Sequelize Dialect (`backend/db/connection.js`, `config/database.js`)
- 현재 `mysql2` 모듈과 `assertVersion()`(MySQL `8.0.16+` 강제 검사)에 의존한다.
- 전환 시 `dialect: 'postgres'`, `pg` / `pg-hstore` 드라이버, Supabase SSL 옵션(`dialectOptions: { ssl: { require: true, rejectUnauthorized: false } }`), `assertVersion()`의 PostgreSQL 버전 체크 분기가 필요하다.

### 2.2 자료형 및 DDL 문법 차이 (`001`, `006`, `007` 마이그레이션 & `models.js`)

| 항목 | 현재 MySQL 8.0 | PostgreSQL (Supabase) 전환 방안 |
|---|---|---|
| 부호 없는 정수 | `BIGINT UNSIGNED`, `INT UNSIGNED`, `TINYINT UNSIGNED` | `BIGINT`, `INTEGER`, `SMALLINT` + `CHECK (col >= 0)` (Sequelize `UNSIGNED` 제거) |
| 자동 증가 PK | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` + 이관 후 `setval()` 시퀀스 재설정 필수 (현재 `smartphones` AI=`90000303` 등 점프 존재) |
| 바이너리 세션 키 | `BINARY(32)` (`sessions.sid_hash`) | `BYTEA` + `CHECK (octet_length(sid_hash) = 32)` |
| 날짜·시간 & 자동갱신 | `DATETIME(3)`, `ON UPDATE CURRENT_TIMESTAMP(3)` | `TIMESTAMPTZ(3)` + `updated_at` 자동 갱신용 `BEFORE UPDATE` 트리거 함수 작성 |
| JSON 검증 | `JSON` + `CHECK (JSON_TYPE(col) = 'OBJECT')` | `JSONB` + `CHECK (jsonb_typeof(col) = 'object')` (인덱싱·조회 성능 유리) |
| 인라인 `ENUM` | `ENUM('private','public')` | `VARCHAR(16)` + `CHECK (col IN (...))` 또는 `CREATE TYPE` |
| 생성 컬럼 (`target_key`) | `CONCAT('s:', sku_id)` (`STORED`) | PostgreSQL `CONCAT`은 `IMMUTABLE`이 아니므로 `'s:' || sku_id::text` 연산자 사용 필수 |
| 문자셋 / 콜레이션 | `utf8mb4_0900_ai_ci`, `ascii_bin` | DB 기본 `UTF8` 사용. 대소문자 무시 비교가 필요하면 `LOWER()` 또는 `citext` 적용 |

### 2.3 서비스 코드 내 MySQL 전용 SQL 쿼리 수정 대상
- **`backend/services/catalog-recommendation-engine.js` (`fetchPublicCatalogCandidates`)**:
  - `CAST(m.id AS CHAR)` → `CAST(m.id AS TEXT)` (또는 `m.id::text`)
  - `NOW(3)` → `NOW()` (PostgreSQL `NOW()`는 기본적으로 마이크로초 정밀도 `TIMESTAMPTZ` 반환)
  - `m.is_test = 0` → PostgreSQL `BOOLEAN` 타입이므로 `m.is_test = FALSE` (또는 `0/1` 대신 boolean 비교)
- **`backend/db/migrations/007-common-catalog.sql` 및 `ON DUPLICATE KEY UPDATE`**:
  - `ON DUPLICATE KEY UPDATE` → PostgreSQL `ON CONFLICT (...) DO NOTHING` / `DO UPDATE SET ...`로 변경.
- **기타 Raw Query 파일**:
  - `smartphone-catalog.js`, `danawa-price-sync.js`, `catalog-import.js` 등에서 백틱(`` ` ``), `INSERT IGNORE`, `DATE_FORMAT`, `IFNULL` 등 MySQL 전용 문법 전수 점검 필요.

### 2.4 이관 전략 권고 (이중 카탈로그 유지 vs 통합)
- 단기 복제본 전환 시에는 기존 서비스 로직(`recommendation-ranker.js` vs `catalog-recommendation-engine.js`)과 호환성을 유지하기 위해 **스마트폰 전용 테이블 + 공통 카탈로그 테이블 15개 구조를 그대로 PostgreSQL 스키마로 변환**하고, 스냅샷 테이블 2개와 테스트 유저 데이터는 제외하여 이관하는 것이 가장 안전하다.
- `owned_devices.ck_owned_category` 제약에는 `'smartwatch'`, `'earbuds'`, `'speaker'`를 추가하는 것을 권장한다.
