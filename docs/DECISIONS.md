## D-021 — 인증 구현과 운영 경계 (2026-11-09 23:15:55 KST)

D-013 인증 계약을 express-session 1.19.0+기존 sessions 테이블의 직접 Store로 구현한다. 추가 세션 테이블/자동 sync 없음. DB에는 원본 SID 대신 SHA-256 및 최소 payload만 저장하며 cookie 메타데이터는 Store에서 복원한다. 로드한 세션의 set/touch는 유효한 기존 행 UPDATE만 허용하여 logout 후 재생성을 방지한다.

기존 Node 내장 scrypt 비용과 동시 2개를 유지한다. 운영/로컬 cookie·APP_ORIGIN·SESSION_SECRET 검증, 신뢰 프록시는 명시적인 loopback 설정만 허용. 로컬 .env에 생성한 무작위 secret은 재사용하고 예시에 기록하지 않는다. 실행 환경 변수가 파일보다 우선한다.

단일 인스턴스 메모리 rate limit을 사용하며 한도 메모리 10,000키와 인증 경로 분당 120회 IP 제한을 추가했다. 재시작/다중 인스턴스의 제한 공유, 만료 세션행 주기 정리는 향후 운영 작업이다. 중복 가입은 설계의 409 일반 충돌 응답, 로그인은 계정 존재 구분 없는 401. 운영 HTTPS와 프록시의 실제 전달 검증은 배포 시 별도로 수행한다.

## D-022 — 프로필·보유 기기 API 구현 경계 (2026-11-09 23:27:14 KST)

기존 REST 계약을 유지한다. 공통 성향과 스마트폰 선호는 GET/PUT /api/profile의 common/smartphone으로 구분하며 별도 스마트폰 선호 엔드포인트를 중복 생성하지 않는다. PUT은 전체 교체·사용자 확인 저장이며 expected_version 필수다. 선택 필드는 null/빈 배열 기본값, usages/spending_style 및 common/smartphone 객체는 필수. 자연어 원문/분석 초안 저장 API는 만들지 않고 확인된 lifestyle_note(300자)만 저장한다. 추천 요청 예산·필수조건은 프로필에서 거절한다.

기존 세션/CSRF 미들웨어를 /api 공통 계층으로 이동(health/db 제외). 기존 단일 IP 분당 120회 제한은 이 계층을 통과하는 전체 API에 적용한다. 가입/로그인 전용 제한은 기존 라우트에 유지한다. 사용자 행과 프로필 행을 순서대로 잠가 버전·20개 상한의 동시성 검증을 수행한다. 최대 version에 도달하면 VERSION_EXHAUSTED 409로 거절한다.

보유 기기 POST/PUT 응답은 {data:{device,profile_version}}, DELETE 성공은 204이므로 이후 GET /profile로 버전을 갱신한다. 조회는 {data:[...],next_cursor}; 기본 20/최대 50, 문자열 ID의 오름차순 커서. 검색은 q 필수 1~100자이며 검색어를 SQL 파라미터/리터럴 부분문자열로 처리한다. 소유권은 세션 user_id로만 결정한다.
