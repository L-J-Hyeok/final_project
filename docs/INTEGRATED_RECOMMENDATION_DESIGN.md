# 범용 하이브리드 추천 엔진 설계

기준일: 2026-11-13 (Asia/Seoul). [팀 요구사항](TEAM_REQUIREMENTS.md)을 기술적으로 구체화한다. 아래 **확정**은 요구사항, **제안**은 구현 전 협의할 방식이다. 현재 SQL·API 계약을 자동 변경하지 않는다.

기존 [아키텍처](ARCHITECTURE.md)·[가격 계획](PRICE_COLLECTION_PLAN.md)을 재사용한다. Phase 5 변경의 동작·정확성·완료 여부는 이번에 검증하지 않는다. 현재 수량이나 과거 테스트 통과 수를 설계의 전제로 고정하지 않는다.

## 확정: 책임 경계

AI는 자연어·프로필·과거 기기 성향을 해석하고, 사양의 기술적 의미와 허용된 전문 자료를 정리하며, 검증된 결과를 설명한다. 일반 지식만으로 성능 수치를 확정하지 않는다.

로컬 엔진은 DB 후보 조회, 예산·필수 조건, 제품 호환성, 검증 자료 선택, 개인 가중치, 정규화, 가성비, 최종 순위를 담당한다. AI가 순위·예산·제품 ID를 바꾸지 못하도록 최종 출력도 검증한다. 공개 DTO에서 내부 점수·가중치를 제외한다.

## 제안: 공통 파이프라인

1. 인증·프로필 버전·선택 기기 소유권 확인. 자연어 분석 초안을 사용자에게 확인받고 현재 명시 조건을 우선한다.
2. 제품군 설정을 선택한다. 미지원 제품군·미완성 설정은 지원 불가 또는 추가 정보로 응답한다.
3. 카테고리 어댑터가 공개 승인된 DB 모델·실재 옵션을 조회한다. 색상×용량을 임의 조합하지 않고 실제 ID를 유지한다.
4. 필수 조건·호환성·가격 적격성으로 후보를 제한한다. 현재 스마트폰 최근 3년 정책은 명시적으로 변경하기 전까지 유지하며 보유 기기 평가는 연식 제한을 적용하지 않는다.
5. 검증된 성능 근거 캐시를 정확한 제품·옵션에 연결한다. 결측은 NULL, 비교 불가능은 별도 상태로 유지한다.
6. 동일 측정 기준 안에서 평가 항목을 정규화하고 사용자 가중치로 로컬 순위를 계산한다.
7. 일반 추천은 적합한 제품 순위를, 업그레이드는 교체 필요성과 이득·손실·비용을 별도로 판단한다.
8. AI에 승인된 제품 ID·서버 순서·검증 근거만 제공해 설명을 생성한다. 불필요한 개인 원문과 내부 점수·가중치는 전송하지 않는 방향을 우선한다.
9. ID·순서·조건·근거·가격 최신성을 재검증하고 스냅샷을 저장한다. 사용자 응답에는 출처·가격 성격·불확실성·자연어 이유를 포함한다.

필요할 때 전문 자료를 조사하는 기능은 현재 추천 요청에서 무제한 웹 검색을 허용한다는 의미가 아니다. 별도 허용된 수집·검증 경로로 반영한다. 이번에는 웹 조사 자체를 수행하지 않는다.

## 제안: 제품군별 설정

공통 코어와 카테고리별 `spec definitions / eligibility / compatibility / metric normalization / preference weights / evidence policy`를 분리한다. 명칭은 설계 예시이며 새 파일·테이블의 확정 명세가 아니다.

| 제품군 | 주 평가 항목 예시 | 호환성·검증 주의점 |
|---|---|---|
| 스마트폰 | 용도별 성능·카메라·사용 시간·휴대성 | 국내 옵션, OS·생태계, 배터리 용량과 실측 시간 구분 |
| 태블릿 | 화면·펜·앱 작업·휴대성 | 펜/키보드 세대·앱 지원, 부속품 비용 |
| 스마트워치 | 센서·기능·배터리·착용성 | 연결 스마트폰 OS·지역 기능; 칩셋 점수 중심 평가 금지 |
| 스피커 | 음질·출력·지향성·연결성 | 측정 공간·볼륨·코덱·사용 환경 |
| 무선이어폰 | 음질·ANC·통화·착용·배터리 | 코덱·호스트 OS·측정 조건; 착용감의 개인차 |
| 노트북 | CPU/GPU·실작업·화면·휴대성 | 전력 설정·냉각·RAM 구성·실측 환경 |

제품군의 데이터와 메타데이터가 준비되면 공통 핵심 코드를 재작성하지 않는 것이 목표다. 현재 6개 DB·평가 설정이 존재한다는 뜻은 아니다. PC-FIT의 조합·부품 호환성은 후속 별도 도메인이다.

## 제안: 성능 근거와 캐시

근거 레코드는 제품/옵션 식별, 출처 URL·제공자, 측정 항목·값·단위, 도구/벤치마크 버전, OS·전력·측정 환경, 측정/게시/확인 시각, 검증 상태, 사용 권한과 갱신 상태를 관리한다. 실제 컬럼·테이블은 DB 담당과 협의한다.

AI 추출 → 원문·제품 식별·단위 검증 → 비교 가능 집합 분류 → 승인 → 캐시 반영 순서를 제안한다. 버전·환경이 다른 점수는 바로 혼합하지 않는다. 캐시 키는 옵션·지표·버전·환경·출처를 포함하고 변경 출처·재검증 기한에 따라 필요한 자료만 갱신한다. 미승인·출처 불명·기한 경과 자료는 정책에 따라 제외/재검토하며 자동 승인하지 않는다.

Geekbench·3DMark·Cinebench·Notebookcheck·RTINGS·제조사는 후보일 뿐 사용 허가가 아니다. 이용약관·robots.txt·저장·재배포·AI 이용 권한을 별도로 확인하고 우회 수집하지 않는다. 측정 환경에 따라 실제 성능이 다를 수 있음을 표시한다.

## 제안: 점수·가성비·결측 정책

정규화 기준 집합과 버전을 고정하고 높을수록 좋은 값, 낮을수록 좋은 값, 목표 범위·정성 항목을 구분한다. 예시 내부식은 `합계(사용자 가중치 × 정규화된 검증 항목값)`이며 실제 가중치·임계값·가성비 함수는 미확정이다. 결측을 0으로 치환하거나 근거 적은 제품이 유리해지도록 남은 가중치를 무조건 재분배하지 않는다. 최소 근거 충족도와 비교 가능성을 먼저 검사한다.

가격은 verified_sale / reference_sale / official_launch를 구분한다. 운영의 기존 최신성·배송비·구매 조건 규칙을 보존하고, 개발용 대체 가격을 실제 구매가로 표시하지 않는다. 가격 NULL이면 가격 기반 순위·가성비를 확정하지 않는다. 출시가와 현재가 차이는 양쪽 근거가 적격일 때만 표시한다.

## 일반 추천·업그레이드·비교의 분리

일반 추천은 보유 기기 없이도 동작한다. 업그레이드는 소유권이 확인된 현재 기기와 사용자 만족·불편·교체 이유를 필수 맥락으로 삼는다. 비공개·단종 보유 기기도 검증 가능한 사양은 평가하되 신규 공개 후보로 승격하지 않는다.

KEEP은 현재 필요 충족과 유지 이득, REPLACE는 불편 해결에 관련된 검증 개선과 비용, DEFER는 결론/구매를 미룰 근거, CLARIFY는 필요한 최소 추가 정보로 구분한다. 자료 부족과 개선 없음은 구별한다. 기존 wire status `recommend`를 REPLACE 의미로 사용하는 계약은 유지하며 이름 변경은 별도 계약 검토한다. 후보 개수 제한이 유지 판단을 가로막거나 단일 미측정 항목이 전체 후보를 자동 탈락시키는 문제를 후속 점검한다.

비교는 우세·동률·단순 차이·자료 부족·비교 불가를 지표 정책으로 판정한다. 개인 선호 장단점과 객관적 우세를 구분한다. AI 설명 실패에도 기존 수치 비교는 유지한다. 과거 추천은 당시 스냅샷으로 보존하고 현재 유효성·재평가는 별도 표시한다. 명시적 개인정보 삭제 정책은 유지한다.

## 실패 처리 및 미해결 결정

- 조건 충돌/미입력: 필요한 질문만 반환. 후보 없음: 조건 자동 완화 금지.
- 자료 부족: 결측·비교 불가와 필요한 자료 표시. AI의 추측으로 채우지 않음.
- AI 해석 실패: 구조화 입력으로 전환 제안. 설명 실패: 확정된 로컬 결과와 검증 사실 템플릿 제공을 제안. 재시도·비용 한도 필요.
- AI가 제품·순서·수치 변경: 결과 거부. 갱신된 가격·조건과 충돌: 재검증 후 재요청 안내.
- 추가 예산 후보는 본래 예산 내 순위와 분리하고 사용자 선택 없이 기본 조건을 바꾸지 않음.

미결정: 제품군별 DB 계약, 근거 이용 권한, 측정 환경 동등성, 정규화 기준·가중치·동률 처리, 최소 자료 충족도, 가성비 계산, 캐시 TTL, 수집 승인 주체, 업그레이드 유의미성 임계값, AI 실패 응답 계약·비용 한도, 내부 점수 접근 권한·보관 정책. 구현 전 합의와 버전 관리가 필요하다.
