# 제품 데이터 수집 표준

2026-11-14 — 조사 제출 양식. **CSV 자동 DB 등록 기능은 구현되어 있지 않다.** 검토 후 기존 관리자 등록·승인 절차로 반영한다. 스마트폰 MVP는 국내 무약정 단품 자급제만 공개하며, 다른 제품군은 향후 확장이다.

## 1. 모델과 옵션, 가격을 나누어 기록

- `product_models.csv`: 모델 한 종류당 한 줄. `model_key`는 조사자가 정하는 연결 이름(예: samsung-s25-kr). DB ID가 아니다. 제조사·제품명·국내 모델번호·출시일·공통 사양·공식 링크·판매 채널 근거를 기록한다.
- `product_variants.csv`: **실제 판매 조합 하나당 한 줄**. `variant_key`로 가격과 연결한다. 저장 용량·RAM·색상·통신 방식·국가가 달라지면 별도 옵션 여부를 확인한다. 색상 목록과 용량 목록을 곱해서 행을 만들지 않는다.
- `product_prices.csv`: 정확한 옵션과 관측 시점당 한 줄. 다른 색상·용량·RAM의 가격을 복사하지 않는다.
- 국내 모델번호는 모델 식별자, `official_sku`는 제조사/공식 판매처의 세부 상품 품번이다. 내부 `smartphone_id`, `variant_id`는 등록 담당자가 기존 DB와 대조해 부여·재사용한다. 조사자가 임의 생성하지 않는다.

## 2. 출처와 검증

우선순위는 한국 제조사 제품/지원 페이지 → 제조사 국내 출시 보도자료 → 정확한 국내 옵션이 명시된 신뢰 가능한 단품 판매 페이지다. 공식몰과 공식 인증 판매점은 구분한다. 제목·URL만으로 사양을 확정하지 않는다.

`source_url`, `checked_at`(시간대 포함), 확인한 항목, 누락 항목을 기록한다. 보조 출처는 제조사 출처처럼 표기하지 않는다. 지역·용량·RAM·색상과 출처 제품이 일치해야 한다. 한 출처가 모든 필드를 검증한다고 가정하지 않는다.

옵션 검증과 SKU 검증은 독립적이다. 실제 국내 판매 옵션이 증명되면 SKU가 비어 있어도 `option_verification_status=verified`가 가능하다. 품번은 직접 확인한 경우에만 `sku_verification_status=verified`로 쓴다. 조사자의 검증 완료는 관리자 공개 승인과 같지 않다.

국내 통신사 전용 모델은 `carrier_exclusive`와 통신사를 기록하고 자급제 공개·수집 대상에서 제외한다. 데이터 자체를 삭제하거나 가짜 제품으로 반려하지 않는다. 모델번호 끝 문자만으로 자급제 여부를 추정하지 않는다.

## 3. 사양·NULL·중복 규칙

| 제품군 | 반드시 확인할 식별·구성 | 확인 가능한 상세 사양 |
|---|---|---|
| 스마트폰 | 국내 모델번호, 출시일, 용량·색상 조합, 판매 채널 | 칩셋, RAM, 화면/주사율, 카메라, 배터리, 무게 |
| 태블릿 | 모델번호, Wi-Fi/셀룰러, 용량·색상 조합 | 칩셋, 화면, 펜 지원, RAM, 배터리, 무게 |
| 스마트워치 | 모델번호, 크기, Bluetooth/LTE, 소재·밴드 구성 | 호환 OS, 센서, 화면, 배터리 |
| 노트북 | 정확한 국내 SKU, CPU/GPU/RAM/SSD 구성 | GPU 전력, 화면, 확장성, 무게, 배터리 Wh |
| 이어폰·기타 | 정확한 모델/SKU, 국내 단품 판매 여부 | 연결 규격, 코덱, ANC, 배터리, 호환성 |

선택 사양은 `category_specs_json`에 단위와 함께 기록할 수 있다. 이는 조사용 필드이며 새 DB 테이블이나 자동 변환을 뜻하지 않는다. 폴더블 내부/외부 화면, RAM/VRAM/저장 용량, 배터리 mAh/Wh를 섞지 않는다.

CSV 빈칸은 미확인(NULL)이다. `0`·`false`는 실제 확인된 값에만 사용한다. 제조사 미공개 RAM·배터리 값은 추측하지 않으며, 기존 제3자 값을 공식 검증값으로 승격하지 않는다. 누락 사유는 `missing_fields`와 `notes`에 적는다. 기존 확인값을 빈칸으로 덮어쓰지 않는다.

모델 중복은 브랜드+국내 모델번호로 먼저 확인하고 제품명 차이도 대조한다. 옵션은 모델+용량+RAM(NULL 포함)+색상 및 제품군별 연결 규격으로 확인한다. 동일 SKU가 서로 다른 옵션에 연결되면 등록을 멈추고 검토한다. 기존 ID/FK는 재생성하지 않는다.

## 4. 가격과 공개·수집 자격

- 공식 출고가는 옵션 양식에 별도 기록한다. 현재 판매가로 대체하지 않는다.
- `verified_sale`, `reference_sale`, `official_launch`를 구분한다. 가격이 없으면 가격 행을 만들지 않는다.
- 다나와 상품 링크는 판매처 직접 구매 링크가 아니다. 실제로 제공된 링크만 기록한다.
- 배송비·재고·구매 조건을 모르면 빈칸/unknown. 카드·멤버십·약정·해외판·중고 조건을 일반 신품 자급제 가격으로 섞지 않는다.
- `observed_at`은 실제 확인 시각, `expires_at`은 정책상 만료 시각이다. 기존 24시간 제한과 서버 검증을 유지한다. 과거 기록을 현재 가격처럼 갱신하지 않는다.
- 제품 공개 가능, 가격 매칭 준비 완료, 외부 수집 권한 확보, 실제 가격 수집 성공은 서로 다른 상태다. 정확한 가격 매칭과 허용된 접근 조건을 확인해야 한다.
- 가격·SKU가 없더라도 검증된 제품은 검색·상세·비교 가능하다. 가격이 필요한 추천 정책은 별도로 유지한다.

## 5. 실제 작성 예시

1. 모델 키 `samsung-s25-kr`, 브랜드 samsung, 모델 Galaxy S25, 국내 모델번호 `SM-S931N`을 모델 표에 기록한다.
2. 옵션 키 `s25-512-silver`, 모델 키 `samsung-s25-kr`, 512GB, RAM 12GB, 실버 쉐도우, SKU `SM-S931NZSFKOO`를 옵션 표에 기록한다. 근거: [삼성 공식 자급제 제품](https://www.samsung.com/sec/smartphones/galaxy-s25-s931/SM-S931NZSFKOO/).
3. 가격을 확인하지 않았다면 가격 표에는 행을 추가하지 않는다. 출고가도 확인되지 않았다면 빈칸으로 둔다.
4. 등록 담당자가 모델·옵션 중복과 출처를 검토하고 기존 ID에 연결한다. CSV를 실행하거나 일괄 업로드하는 단계는 없다.

출처 이용약관·자료 재사용 권한을 확인한다. 접근 제한 우회·무단 대량 수집·이미지/설명 복제를 하지 않는다. 공유 파일에는 계정·비밀번호·API 키를 넣지 않는다.
